# 1レッスンの構成と段階的な公開

参加者の入口は、毎回1冊のipynbにそろえます。
ノートブックが1冊であることと、処理本体をすべてセルに書くことは別です。
共通処理はPythonコードとして管理し、参加者には手作業でファイルを集めてもらいません。

## 参加者から見える1レッスン

各冊は次の順番です。

1. **目的・前提・達成条件**：何を確認すれば終わりか。
2. **準備**：T4確認、内蔵プログラムの展開、固定依存関係のセットアップ。
3. **設定**：ステップ数、エピソード数など、今回変更する値。
4. **実行**：小さい確認から始め、本実行に進む。
5. **結果確認**：画像、動画、ログ、必要なら指標。
6. **考察と保存**：確認課題とDriveへの保存。

前の冊で学んだ知識は使いますが、前の冊のPython変数やランタイム内ファイルは前提にしません。
学習済みモデルやデータが必要な冊では、指定した保存先から読む準備セルを用意します。

## 開発側の配置

```text
vla_workshop/
├── README.md                         # 公開済み・準備中の一覧
├── colab.ipynb                       # 各冊への案内のみ
├── lessons/
│   ├── 00_environment/
│   │   ├── README.md                 # 目的・達成条件・読むコード
│   │   ├── colab.ipynb               # 参加者が開く1冊（生成物）
│   │   └── run.py                    # 共通処理を呼ぶ薄い入口
│   └── 01_smolvla_inference/
│       ├── README.md
│       ├── colab.ipynb
│       └── run.py
├── src/vla_workshop/                 # 環境接続・モデル接続・記録などの共通処理
├── configs/                          # 共通の実行条件
├── requirements/                     # 固定した依存関係
├── notebooks/lesson.template.ipynb    # 各冊の説明・セルの原稿
└── scripts/build_colab_notebook.py    # 原稿＋共通コードから各冊を生成
```

各冊に同じ共通コードを自動同梱します。準備セルでColab内に展開し、実習セルから呼びます。
参加者が配布時に必要とするのはipynbだけです。ライブラリ・モデルのダウンロードは別途行います。
共通ソースを直したら各冊を再生成するので、手で複製したコードの版ずれを避けられます。
教材内でコードを読むときは、展開先の`src/vla_workshop/`をColabのファイル欄から開けます。

## 内容が増えたときの分担

| レッスン | ノートブックに置く内容 | 共通コードに置く処理 |
| --- | --- | --- |
| 環境確認 | 観測・行動を表示して意味を確認する | 環境の生成、観測・行動の変換 |
| 推論 | モデル設定、実行、動画と行動の確認 | モデルの読み込み、前処理、推論、後処理 |
| 評価 | タスク・試行条件、成功率と失敗例の確認 | 複数試行、seed管理、集計、記録 |
| fine-tuning | データ選択、学習設定、学習曲線、前後比較 | データ読込、学習ループ、checkpoint保存 |
| データ収集 | 収集条件、開始・終了、採否確認、再生 | 入力装置との接続、記録、検証、変換 |

短い説明用の処理はセルに書いて構いません。長いループや複数の冊で使う処理を共通コードに移します。
データ収集では入力方法・中断時の保存も設計するため、収集プログラム全体をセルに詰め込まない方針です。
高頻度の記録はランタイム内へ保存し、確認後にまとめてDriveへ保管します。
大きな動画・データセット・モデル重みをipynb自体には埋め込みません。

## 公開順

最初は00・01だけ配布します。02以降はREADMEの「今後追加」に残します。
実行できない空のノートブックを先に配る必要はありません。
次の冊を実装・確認した段階で一覧へリンクを追加し、その冊を共有Driveへ置きます。

各冊を独立して実行できるため、公開済みの教材に取り組みながら、次の冊を準備できます。
