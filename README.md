# VLA Workshop

robosuiteでSmolVLAを動かし、データの確認・学習・収集を経て、LIBEROでの改善実験へ進む教材です。
**各回のipynbと、同じフォルダのPython・設定ファイルを一式で配布します。**

```text
vla_workshop/
├── 00_environment/              # 環境・観測の確認
├── 01_smolvla_inference/         # SmolVLAの読み込みと推論
├── 02_libero_evaluation/         # LIBERO評価
├── 03_dataset/                  # データ確認・再生
├── 04_finetuning/               # 既存データで学習
├── 05_collection/               # モデルの動作の収集・採否・変換
├── 06_collected_finetuning/      # 自分のデータで再学習
├── 07_improvement/              # 条件をそろえた改善比較
└── _dev/                        # 教材を更新するための共通ソース
```

長時間学習や最終評価での成功率は未計測です。
[検証状況](_dev/docs/validation.md)で、実際に確認した範囲を区別しています。
講師は用意した教材を1回ずつ案内でき、全員に一度に取り組んでもらう必要はありません。

## 配布と実行

1. 講師は、その回のディレクトリを一式で配布します。ipynbだけでは動きません。
2. 参加者はフォルダを自分のDriveに置き、ipynbをColabで開きます。
3. 最初のセルの`LESSON_DIR`に、その回のフォルダのパスを指定します。
4. 必要ファイルを確認し、この回のコードだけをColab内の作業場所へコピーします。
5. 準備 → 設定 → 実行 → 結果確認 → 考察 → Driveへの保存と進めます。

結果はフォルダのまま保存します。05の保存セルは06で使うデータのパスを、
04・06の保存セルは07で使うモデルのパスを表示します。

Driveを使わず、最初のセルで今回のファイルをまとめてアップロードする方法も選べます。
ipynbの冒頭に必要ファイルを列挙しています。足りなければ、その名前を表示して停止します。

環境準備と実行するPythonコードはセルに明示し、長い補助処理は隣の`.py`から読み込みます。
例えば01では`smolvla.py`、`robosuite_env.py`、`rollout.py`と`lift.json`を使います。
教材の`vla_workshop`パッケージの読み込み、教材リポジトリのclone、コードの埋め込み・展開は行いません。

依存ライブラリと公開モデル・データは実行時にダウンロードします。
依存関係を固定するため、各回の作業場所に専用Pythonを作り、セル内の`run_python(...)`で実行します。
参加者がCLIで別途起動する手順はありません。
大きなデータ・重み・動画はノートブックに埋め込まず、Driveなどへ保存します。

## 各回のポイント

- **00・01**：標準Lift/Pandaでの接続確認です。ここでの成否はLIBEROのスコアではありません。
  00はモデルの推論をせず、EGLによる描画にGPUを使う設定です。
- **02**：最初は20ステップの接続確認を選べます。成功率を比較するときは、タスク・初期状態・ステップ上限を全員でそろえます。
  標準設定はLIBERO-Spatialの1タスクです。全ベンチマークのスコアとは区別します。
- **03**：固定revisionの`lerobot/libero`から、02で評価するタスクと同じ指示のエピソードを読み込みます。動画を含むため初回取得に時間がかかります。
  公開データのメタデータは10 fps、シミュレータの制御は20 Hzです。フレーム番号と物理的な制御周期を混同しないでください。
- **04**：初期設定は10ステップ・batch size 1です。VLMを固定し、expertなど学習対象のパラメータを更新します。
  正規化は元のモデル付属の統計を保ちます。検証lossは固定した小さな検証ミニバッチの値です。
- **05**：現時点の収集は、モデルのrolloutと任意のスクリプト補正です。`collector.py`を編集できます。
  人によるリアルタイム操作の記録UIは未実装です。失敗も候補として保存し、動画を確認して採用番号を指定します。
- **06**：05の変換済みデータを指定します。初期設定では学習2本・検証1本が必要です。
  エピソードは重複させず、04の既存データだけの結果と比較します。
- **07**：`experiment.py`を編集します。配布例は一度に実行する行動数を1→2に変える比較です。
  タスク・初期状態・seed・環境などが一致しない結果は、比較処理が拒否します。
  検証結果で候補を決めた後、別の初期状態で最終評価します。

学習用・検証用エピソードは分けますが、開始モデルの事前学習データとの重複は不明です。
成功率だけでなく、試行数、変更した条件、データ量、代表動画、失敗傾向と再実行方法を共有してください。
